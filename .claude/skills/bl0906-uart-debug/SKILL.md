# BL0906 UART 调试

## 何时使用

- BL0906（或同类 Belling UART 电量表）没有读数、全部超时。
- 日志出现 `Checksum mismatch`、`Timeout reading register`、`Retrying register`。
- 自制板与商用开发板表现不一致。
- 需要把阻塞式 UART 读取改成非阻塞状态机。

## 协议速查

- 19200 8N1，主机发 `0x35 + 寄存器地址`。
- 从机回 4 字节：`Data_L, Data_M, Data_H, SUM`。
- 校验：`SUM == (地址 + L + M + H) ^ 0xFF`。
- 功率/总功率为有符号 24 位；电流/电压/电量为无符号 24 位。
- 空载时功率/电量数据字节通常为 `00 00 00`，其 SUM = `地址 ^ 0xFF`。
- 命令是 2 字节，回复是 4 字节；不存在 1 字节回复。

## 日志分类表

| 日志特征 | 含义 | 处理 |
|---|---|---|
| 没有任何 `0xXX = ...` | 读路径不通 | 进入“连接层检查” |
| `Checksum mismatch` 与 `Timeout` 交替 | 回复迟到/错位；上一条回复被下一条读走 | 帧间隔 + 失败重试 + 重同步；用滑动窗口 |
| `Timeout ... available=0` | **不能证明没信号**：消费型滑动窗口会把字节边收边丢 | 看 `rx_bytes`，不要只看 `available` |
| `rx_bytes=0` | 本次尝试真的一个字节都没收到 | 查 RX 接线、BL0906 供电、共地、TX 是否到 BL0906 |
| `rx_bytes=1`，字节随寄存器地址变化 | TX 串扰；RX 没有被 BL0906 驱动 | 查 TX/RX 是否接反/松动；回环测试 |
| `last=35 XX ...` | 命令回声/串扰 | 滑动窗口会跳过；持续出现则查 RX 驱动 |
| `last=00 FF ...` | 悬空/噪声 | 开 RX 内部上拉；加 10k 外部上拉 |
| 固定 4 字节但校验不过 | 有完整帧但内容不对 | 查波特率、地址、电平 |
| 随机字节、每帧不同 | 波特率/电平错误或严重干扰 | 确认 19200 8N1、共地、3.3V 电平 |

注意：`last=` 是滑动窗口里最后 4 个字节，**最新字节在最后**；每次发送前清空窗口，
日志才只反映本次尝试。

## 串扰字节的识别方法

如果每次只收到 1 个字节，且该字节随寄存器地址变化，可以验证它是不是地址字节的移位：

1. 取地址字节，按 UART LSB-first 展开：start(0) + b0..b7 + stop(1) + idle(1)。
2. 假设 UART 在某个 0 位上误判起始位，从下一位开始采样 8 位。
3. 拼出的字节如果等于日志里的 `last` 最新字节，就是 TX 串扰，不是 BL0906 回复。

本次实测：

| 寄存器 | 收到字节 | 地址字节的采样起点 |
|---|---|---|
| 0x23 | 0xF2 | 从 b3 开始 |
| 0x24 | 0x92 | 从 b0 开始 |
| 0x2C | 0x96 | 从 b0 开始 |
| 0x30 | 0x98 | 从 b0 开始 |
| 0x31 | 0xE6 | 从 b2 开始 |

这类“确定性地随地址变化”的单字节，是 RX 悬空/未被驱动的强证据；随机噪声不会这样稳定。
根因常见于杜邦线松动、TX/RX 接反、BL0906 未上电、未共地。

## 诊断步骤

### 1. 抓完整一轮日志

60s 轮询，确保看到 0x4E 到 0x39 的完整一轮。只贴中间一段容易误判。

### 2. 先判断“有没有字节”，再判断“字节对不对”

在 `WAIT` 状态累计本次尝试读到的字节数，并在超时时打印最后 4 字节：

```cpp
// SEND 前
window_[0] = window_[1] = window_[2] = window_[3] = 0;
window_len_ = 0;
rx_bytes_ = 0;

// WAIT 中每读一个字节
window_[0] = window_[1];
window_[1] = window_[2];
window_[2] = window_[3];
window_[3] = read();
rx_bytes_++;

// 超时
ESP_LOGW(TAG, "Timeout reading register 0x%02X (available=%u, rx_bytes=%u, last=%02X %02X %02X %02X)",
         addr, available(), rx_bytes_, window_[0], window_[1], window_[2], window_[3]);
```

不要用 `available=0` 推断“没信号”。滑动窗口会消费掉无效字节，超时那一刻缓冲区本来就是空的。

### 3. 连接层检查（断电进行）

- 万用表通断：
  - ESP32 GPIO25 ↔ BL0906 TX/SDO（H1.4）
  - ESP32 GPIO26 ↔ BL0906 RX/SDI（H1.3）
  - GND ↔ GND
- 量 BL0906 的 3.3V。
- 边量边轻轻晃动杜邦线；静态通断正常但晃动时断开，就是接触不良。
- 优先更换锁扣线/端子，最终板用连接器固定。

### 4. 回环测试

1. 断开 BL0906 的 TX/RX。
2. 在 ESP32 端短接 GPIO26 和 GPIO25。
3. 用带诊断的固件运行，观察超时日志：
   - 正常：`rx_bytes=2`，`last` 中出现 `35 XX`（两个命令字节）。
   - `rx_bytes=0` 或 1：板子的 RX 路径/引脚有问题，或短接没接好。
4. 回环时不会出现 `0xXX = ...`，因为回声通不过校验和；只看 `rx_bytes/last`。

## 驱动加固规则

- `update()` 只启动一轮，`loop()` 用状态机分步执行，禁止阻塞。
- 每条寄存器单独超时（建议 150ms），超时后重试同一条，最多 2 次。
- 正常回复后留 2ms 帧间隔；失败后留 60ms 重同步间隔再排空 RX。
- 读完回复不要在下一个 loop 立刻发下一条命令。
- 解析用逐字节滑动窗口，只有校验和匹配当前地址的 4 字节才接受。
- 收到无效字节时继续滑动，不要 `drain_rx_()` 把可能的真实回复一起丢掉。
- RX 引脚开内部上拉；外部 10k 上拉更稳。
- 每个寄存器一行日志，便于确认一轮是否完整。

## 验证清单

- `esphome compile` 输出 SUCCESS。
- 烧录后一轮内所有配置寄存器都出现 `0xXX = ...`。
- 无 `Checksum mismatch` / `Timeout` / `Retrying`。
- 空载参考：频率约 50Hz、电压约 220–230V、功率/电量为 0、电流为小噪声底。
- 如接 HA：mDNS 能解析、6053 端口可连、`esphome logs --device <ip>` 握手成功；
  发现不到时在 HA 里按 IP 手动添加。

## 本次案例（2026-10-24）

1. 阻塞式读取导致单轮 567ms，改为非阻塞状态机。
2. `Checksum mismatch` / `Timeout` 交替：迟到回复被下一条读走；
   通过帧间隔、失败重测、60ms 重同步、逐字节滑动窗口解决。
3. RX 收到 `35 XX 00 00`：RX 悬空拾取 TX 命令；开 `INPUT_PULLUP` 后改善。
4. 自制板上每次只收到 1 个随地址变化的字节（0x23→0xF2 等）：
   解码后确认是地址字节的移位，根因是杜邦线松动，换线后 23 个寄存器全部正常。
5. `available=0` 一度被误读为“完全没信号”；加入 `rx_bytes/last` 后才看清是串扰。

## 安全

HLK-PM03 是隔离电源，但市电侧仍然危险。改线、测通断、插拔探头前必须断开市电；
不要带电触摸 BL0906 板的高压区域。
